# Protocol v1 — extension/companion integration contract

The companion binds http://127.0.0.1:9876; WS /ws/v1/session. Both platforms use camelCase JSON fields. Protocol version 1. Browser extension Origin must be chrome-extension://<id>; reject all web origins. Non-browser local setup requests have no Origin. A random pairing token is generated once at .runtime/token (0600); user pastes it into side-panel setup (not bundled into extension source). Authenticate with first JSON `hello` message within 5s. Do not put tokens in URL/logs.

HTTP GET /health -> {status:'ok'|'loading'|'error', ready:boolean, asr:string, translation:string, protocolVersion:1}. GET /capabilities (token Bearer required) -> {protocolVersion:1, languages:string[], models:array, visual:boolean, ...}. POST /v1/config (token required) -> configure source/translation provider, endpoint/model, key (key saved only in Keychain), glossary, knowledge and optional visual settings. GET /v1/config returns redacted config. POST /v1/models/warmup and GET /v1/models/status (authenticated). POST /v1/ocr accepts {image:string} data-url and returns {text:string}. POST /v1/translate accepts {text,sourceLanguage,targetLanguage,glossary?,context?} -> {text,engine}. All local data in project .runtime, models in .models.

Client hello: {type:'hello',protocolVersion:1,token,sessionId,epoch:0,sourceLanguage:'auto'|'en'|'ja'|'ko'|'yue'|'zh',targetLanguage:'zh',mode:'fast'|'accurate',context:string,glossary:[{source,target}],knowledge:[{term,explanation,source}],video:{id,url,title,currentTime:number|null,live:boolean,playbackRate:1}}.

Server ready: {type:'ready',sessionId,epoch,engine:string}. After ready binary frames are little-endian signed int16 mono 16000Hz (100ms = 3200 bytes). Client sends {type:'clock',sessionId,epoch,mediaTime:number|null,capturedAt:number,playbackRate:number,paused:boolean} with Date.now timestamps every 250ms. Server derives media times using audio sample offsets anchored by clocks, never result-arrival currentTime.

Client control: {type:'reset',sessionId,epoch:newNumber,mediaTime:number|null,reason:'seek'|'video'|'language'|'resume'|'navigation'}; {type:'pause'|'resume'|'stop',sessionId,epoch}; {type:'context',sessionId,epoch,text:string}; {type:'translate',sessionId,epoch,segmentId,revision,text,sourceLanguage,targetLanguage}. Reset cancels current ASR processor and pending translation and starts new epoch. Pause suppresses emission and clears inference buffers; resume starts new epoch in extension.

Server subtitles: {type:'subtitle',sessionId,epoch,segmentId:string,revision:number,phase:'interim'|'final',sourceText:string,translatedText?:string,sourceLanguage:string,start:number,end:number,mediaTime:number|null,createdAt:number,engine:string}. start/end are session audio seconds in epoch. Server can send newer subtitle revision with translatedText. Never emit translatedText:'' to overwrite a real translation. An actual translation failure sends {type:'status',level:'warning',code:'translation_unavailable',message}. Browser Translator draft may render while backend translation is pending; only overwrite draft with a newer final translation for the same source revision.

Server markers: {type:'markers',sessionId,epoch,segmentId,revision,markers:[{term,explanation,source,confidence,type:'meme'|'knowledge'}]}; async timeout 1500ms, queue 1, no blocking ASR/translation. Server status: {type:'status',level:'info'|'warning'|'error',code,message,sessionId?,epoch?}. Server diagnostics: {type:'metrics',sessionId,epoch,asrMs,translationMs?,backlogMs?}.

Frontend owns history in extension-origin IndexedDB. One session row with tabId,videoId,url,title,startedAt,sourceLanguage,targetLanguage,mode. Segment key [sessionId,epoch,segmentId], revision monotone. Store original, translation, source/target language, times, glossaryVersion, engine and markers. Interim stays in memory; each final is upserted immediately. Translation/marker followups update that row. Content rendering ACK: {kind:'rendered',sessionId,epoch,segmentId,revision,renderedAt:Date.now(),hasTranslation:boolean}; persist timing for acceptance report.

Runtime messages (chrome.runtime): `{target:'background'|'offscreen'|'content'|'panel',kind:string,...}`. UI commands target background: start,stop,settings,select-video,seek,clear-history,export,diagnostics. Background routes capture config to offscreen; offscreen sends server events to background; background sends event envelope to target frame and panels. Content publishes kind:'video-state' / 'video-candidates' / 'rendered'. Extension settings interface and defaults must be shared, not duplicated.
